# Вариант 20 — Газовая котельная

Курсовой проект ПМ.02 «Сопровождение и схемотехническое обслуживание интеллектуальных интегрированных систем», специальность 09.02.08 «Интеллектуальные интегрированные системы», СПб ГБПОУ «Петровский колледж».

**Тема:** разработка и сопровождение виртуальной системы сбора и учёта данных на Arduino.
**Цепочка:** Arduino Uno (Wokwi) → Serial Monitor → `data/log.txt` → Node-RED → SQLite.

> Учебный проект. Не предназначен для управления реальным газовым оборудованием.

Модель Wokwi: https://wokwi.com/projects/477934511917259777

## Параметры варианта

| Параметр | Значение |
|---|---|
| s1 | MQ2, условная шкала метана 0–100 %, вход A1 |
| s2 | потенциометр, давление газа 0–5 бар, вход A2 |
| s3 | PIR, движение 0/1, вход D2 |
| Исполнительные устройства | реле D5 (активный LOW), белый светодиод D3 через R1 = 120 Ом |
| Период опроса | T = 5 с |
| Порог события | s1 > 20 % |

Калибровка MQ2: в Wokwi в «чистом воздухе» датчик выдаёт код АЦП 210, поэтому в скетче шкала s1 считается как `100·(ADC − 210)/(1023 − 210)` с ограничением 0…100 %. Без неё s1 не опускается ниже 20,53 % и событие NORMAL получить нельзя.


## Формат Serial

```
DATA n=1 s1=85.73 s2=0.00 s3=0
EVENT n=1 type=THRESHOLD
```

`DATA` выводится каждый цикл, `EVENT` — только при смене состояния (`THRESHOLD` при переходе через порог вверх, `NORMAL` при возврате). Время в базе: `t_s = n · 5`. Событие `FAULT` формирует Node-RED, если значение вне диапазона (s1: 0–100, s2: 0–5, s3: 0/1).

## База данных

SQLite, две таблицы: `readings` (n, t_s, sensor, value — по одной строке на датчик в цикле) и `events` (n, t_s, type, message). Каждая загрузка полностью заменяет содержимое таблиц, дублей при повторной загрузке нет.

## Запуск

1. Установить Node.js, Node-RED (`npm install -g node-red`) и sqlite3.
2. Из папки проекта: `./start-nodered.sh` (macOS/Linux) или `start-nodered.bat` (Windows). Редактор: http://127.0.0.1:1880. Запускать нужно из папки проекта, иначе относительные пути `data/log.txt` и `db/variant.db` не найдутся.
3. Нажать «Загрузить реальный лог» (или сохранить `data/log.txt` — поток следит за файлом).
4. Посмотреть результат: `./show-data.sh` или `sqlite3 -header -column db/variant.db ".read db/queries.sql"`.
5. Проверка неисправности: кнопка «ТЕСТ FAULT» загружает `data/log_fault.txt`; после неё снова нажать «Загрузить реальный лог».

Ожидаемый результат для `data/log.txt`: 117 строк `readings` (39 циклов × 3 датчика) и 3 события: THRESHOLD (n = 1), NORMAL (n = 23), THRESHOLD (n = 31).

## Проверки без Node-RED

```
node scripts/test-parser.js                                        # разбор журнала и диапазоны
g++ -std=c++17 -x c++ scripts/firmware_host_test.cpp -o t && ./t   # логика скетча на заглушках Arduino
```

## Изменение параметров

При изменении периода меняйте `T_MS` в скетче и `T` в `nodered/parser.js`; при изменении порога — `THRESHOLD` в скетче и диапазоны проверок; затем перезагрузите журнал.
